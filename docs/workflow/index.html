Parallel AI Tailoring

When --jd is provided, jd_tailor.py splits profile.md into section slices and dispatches 7 Claude sub-agents simultaneously via ThreadPoolExecutor. Each agent receives only the profile sections relevant to its task and a focused JSON output schema. Results merge into a single content dict, then a keyword audit pass patches the top remaining JD gaps.

Pipeline Stages
INPUT
Source Inputs
docs/profile.md · docs/JD/ · --jd <url|path>

docs/profile.md is the single source of truth for all resume content. The AI tailoring step is bound by strict instruction to use only facts from this file — nothing is invented or embellished.

A job description is optional. Omitting --jd generates the base profile resume. Providing one triggers the full tailoring pipeline.

Accepted JD sources
→LinkedIn job URL
→Any public job posting URL
→Local .md file
→Local .txt file
LOAD
JD Loader
src/tools/jd_loader.py

Fetches and normalises the job description into clean plain text. For URLs, uses curl with system CA certificates, then BeautifulSoup to strip navigation, footers, and sidebars.

LinkedIn jobs get a dedicated extraction path that isolates the description__text container, trimming "Similar jobs" noise and boilerplate above the actual role description.

Processing steps
1Fetch via curl (–30s timeout)
2Strip script, style, nav, footer
3LinkedIn: target job-details container
4Collapse whitespace, return plain text
AI
AI Tailoring
src/tools/jd_tailor.py · src/tools/claude_client.py

Splits profile.md into named section chunks, then dispatches 7 Claude agents in parallel. Each agent receives only the profile sections it needs and returns a section-scoped JSON fragment. A failed agent is retried once before raising.

The JD is capped at 6,000 chars for content agents to avoid prompt bloat; the meta agent always receives the full JD so the company name — often at the end — is never truncated.

Output dict keys
·meta (company, role, role_slug)
·tagline, competencies
·summary[ ], highlights[ ]
·experience[ ] with bullets[ ]
·technical_skills[ ], certifications[ ]
·education[ ]
GENERATE
Resume Generation
src/generate.py · src/templates/

generate.py loads template generator modules dynamically via importlib and calls build(content) on each. When no JD is provided, generators fall back to their embedded base profile data.

DOCX is generated only once regardless of --layout flag — both PDF layouts share the same DOCX source. The reviewer starts in a background thread as soon as the DOCX path is known, running concurrently with any remaining PDF work.

Generators (ats-friendly)
→ats_friendly_1col_generator.py → PDF
→ats_friendly_2col_generator.py → PDF
→ats_friendly_docx_generator.py → DOCX
REVIEW
ATS Review & Job Tracking
src/tools/reviewer.py · src/tools/job_tracker.py

The reviewer runs in a background thread (saves 60–120s vs. sequential). It passes the content dict and JD to Claude, which produces a structured Markdown report scored on ATS compliance and JD fit.

After the review completes, job_tracker.py appends one row to docs/job_applications.csv, extracting ATS and JD-fit scores from the review file via regex.

Review report sections
·ATS compliance score / 100
·JD fit score / 100 + strengths & gaps
·Top 3 actionable improvements
·Submission channel guide
·20–25 keyword coverage table
